# n8n 알아보기

> 워크플로우 자동화 도구, 가볍게 훑어보기

---

## n8n이 뭐야?

- **여러 앱과 서비스를 연결해 반복 작업을 자동으로 처리**해주는 워크플로우 자동화 도구
- 화면에서 블록(노드)을 끌어다 놓고 선으로 잇는 방식 — **코딩 없이도 자동화 가능**
- 필요하면 직접 코드(JavaScript 등)를 넣어 세밀하게 제어할 수도 있음 (노코드 + 로우코드)
- 읽는 법은 "엔에이트엔"

---

## 어떻게 작동해?

- 기본 구조는 단순함: **"이런 일이 생기면(트리거) → 이런 작업을 한다(액션)"**
- 데이터가 노드에서 노드로 흘러가며 점점 가공됨
- 예시:
  - 새 이메일이 오면 → 내용을 요약해서 Slack으로 보내기
  - 구글 폼 응답이 들어오면 → 스프레드시트에 정리 + 알림
  - 매일 아침 9시 → 날씨 API 호출해서 메신저로 전송

---

## n8n의 특징

- **오픈소스** — 내 서버에 직접 설치(셀프 호스팅)해서 무료로 사용 가능
- **셀프 호스팅 가능** → 데이터를 외부에 안 넘기고 내부에서 처리하고 싶을 때 강점
- 수백 개의 앱 연동 노드 제공 (Gmail, Notion, Slack, OpenAI 등)
- 연동 노드가 없는 서비스도 **HTTP Request 노드**로 거의 다 붙일 수 있음 (만능 칼)
- 클라우드 유료 버전도 별도로 있음 (설치 없이 바로 사용)

---

## 비슷한 도구와 비교

- 대표적인 경쟁 도구: **Zapier, Make(구 Integromat)**
- n8n의 차별점:
  - **셀프 호스팅 가능** (Zapier·Make는 클라우드 전용)
  - **오픈소스**
  - **코드로 확장 가능**
- 그래서 개발자·기술팀이 특히 선호하는 편

---

## 요즘 뜨는 활용: AI 워크플로우

- n8n이 최근 인기를 끄는 대표 패턴이 **AI와의 결합**
- 예: RSS로 뉴스 수집 → OpenAI 노드로 요약 → Slack 전송
- "데이터 가져오기 → AI로 가공 → 어딘가로 보내기"를 노코드로 엮을 수 있음

---

## 실제로 누가 쓰고 있어? (활용 사례)

- 전 세계 **3,000개 이상의 기업**이 사용 (Delivery Hero, StepStone, Musixmatch, Unbabel 등)
- **Delivery Hero** (글로벌 음식 배달) — IT 운영 자동화로 **단일 워크플로우 하나가 매달 200시간 이상 절약**
- **StepStone** (채용 플랫폼) — **200개 넘는 핵심 워크플로우** 운영, 새 데이터 연동 속도가 **25배 빨라짐** (2주 → 몇 시간)
- **Musixmatch** (가사 데이터 서비스) — 4개월 만에 엔지니어링 **47일치 작업량 절약**
- **Field Aerospace** — 정부 제안서 초안 작성을 **2주(3~4명) → 25분에 80% 완성**으로 단축
- **Koralplay** — 결제 관련 고객 지원 티켓의 **약 70%를 자동 처리**
- **Bordr** (소규모 사업) — n8n으로 운영을 자동화해 몇 달 만에 6자리 매출 사업으로 성장
- 공통적으로 많이 쓰이는 패턴:
  - 시스템 간 데이터 통합·동기화 (CRM, ERP 등)
  - IT 운영·장애 대응 자동화
  - 영업 리드 분류·라우팅
  - AI를 활용한 콘텐츠 생성·고객 지원

---

## 직접 해보면 좋은 첫 실습

- 난이도를 조금씩 올리며 핵심을 익히는 순서:
  - 1단계: 수동 실행으로 데이터가 노드 사이를 흐르는 것 보기
  - 2단계: 공개 API에서 데이터 가져오기 (HTTP Request)
  - 3단계: 받은 데이터를 메신저(슬랙/디스코드 등)로 보내기
  - 4단계: 정해진 시간에 자동 실행 (Schedule Trigger)
- 추천 첫 목표: **"공개 API 날씨를 받아 매일 내 메신저로 보내주기"**

---

## 직접 해보며 느낀 점 (실습 후기)

- "디스코드에서 부르면 오늘 날씨를 답해주는 봇" 만들기에 도전
- 날씨 데이터를 받아 가공하는 **핵심 로직은 의외로 쉽고 직관적**
- 다만 **디스코드 메시지를 실시간으로 듣는 트리거**는 n8n 기본 기능이 아니라 까다로웠음
  - 커뮤니티 노드는 n8n 버전 업데이트 때 잘 깨짐
  - 결국 **작은 봇 스크립트 + n8n 웹훅** 조합이 가장 안정적이었음
- 배운 점: **각 도구가 잘하는 일을 맡기고, 안정적인 통로(웹훅)로 잇는 게 정석**

---

## 한 줄 정리

- **n8n = 노코드로 앱들을 엮어 반복 작업을 자동화하는, 셀프 호스팅 가능한 오픈소스 도구**
- 간단한 자동화부터 AI 워크플로우까지, 아이디어를 빠르게 실험해보기 좋음
